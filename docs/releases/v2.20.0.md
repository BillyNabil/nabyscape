# NabyScape 2.20.0 · production foundations

This local candidate extends updates, storage, diagnostics, language resources, accessibility, native architecture packaging and recovery. It is not published yet.

## Updates

Automatic update downloads are separately opt-in and follow the existing daily startup check schedule. Downloads may use a metered connection; installation still requires **Install and restart**. Setup selection follows the running process architecture, with exact official asset identity, size, SHA-256, PE machine and version validation. Existing releases may be unsigned; checksums are an integrity check, not publisher authentication.

The helper waits for the installed app to exit, saves a local executable/JSON-profile recovery copy, installs and waits for initial startup acknowledgement. Installation or startup failure triggers a bounded restore attempt. If an owned installer or new child cannot be confirmed stopped, further mutation is blocked and backups remain available. Manual **Restore previous version** warns that saved JSON profile data replaces later edits. New schema sidecars are reconciled with restored legacy payloads. Update staging is separate from the profile folder to preserve legacy migration behavior. Portable files require manual replacement; legacy-named installed executables require a manual official-setup upgrade first.

## Configuration and diagnostics

Flat JSON documents gain version sidecars, a pending migration barrier, bounded reads, serialized writers, atomic flushed replacements, immutable migration originals and rolling last-good copies. Schema 0 to 1 preserves older classic-panel dimensions. Future schemas and unreadable documents are protected from automatic overwrite, including defaults returned after a temporary failed read. Payload commit is the Save success boundary; recoverable final metadata cleanup cannot roll back a credential already referenced by saved provider settings. Unknown object fields are retained; unknown array-item fields are not merged.

General settings provides an explicit private diagnostics preview, refresh, copy and JSON export. Reports contain controlled versions, architecture, observed storage/service status and a bounded ring of 64 enum-coded events/durations. They exclude user paths/names, endpoints, model identifiers, keys, chat, screenshots, audio and saved profile values. Nothing is uploaded automatically. The existing local errors.log is separate and never included.

## Language and accessibility

English remains the default. Spanish and Indonesian interface resources cover common Settings and AI journeys, with explicit English fallback for untranslated technical text. The initial catalog has 328 translated entries. Conversations, files, notes, model/provider IDs and numeric parsing keep their original semantics.

Language, text size from 100–150%, and forced high contrast are saved through General and applied after reopening. Shared controls have focus outlines, accessible icon names and selected polite status announcements. High contrast pairs the actual dock surface with system text colors, keeps progress and checked-state indicators distinct, and suppresses translucent dock material. Voice caption constraints and explicit idle-date text respect the configured scale. Reduced motion follows the user setting and Windows animation preference. Custom artwork, later visual overrides and live OS theme changes are not comprehensively certified.

## ARM64 and recovery

The app has separate native Windows x64 and ARM64 setup/portable targets with matching update and package metadata. Built-in native speech engines remain restricted to an x64 process/CPU with AVX2/FMA. ARM64 users can configure compatible external local ASR/TTS services or providers; Windows voice and wake word depend on matching installed Windows speech engines. Compiling the native app does not validate every external engine on ARM64 hardware.

Sleep/session, network, audio-endpoint and display events use coalesced recovery work. Active voice, wake listening, requests or sharing are stopped when necessary and require explicit restart/retry. Pending wake rearm is invalidated; work is never replayed automatically. Inactive device changes preserve the assistant status. Resume rechecks timer deadlines, audio state, keep-awake requests and display layout while preserving selected-monitor preferences. Cache refresh uses existing requested locations and normal cache policy; ordinary audio/display changes do not trigger weather requests. Subscriptions and queued work are disposed on exit.

## Verification boundary

Source review and Windows Release build/publish/package metadata checks only. No unit tests, UI automation, screenshots, microphone capture, ASR/TTS inference, provider/Hermes requests, device fault injection, ARM64 execution or performance benchmarks were run, per user instruction. Physical ARM64, mixed-monitor, screen-reader and failure-recovery behavior require later runtime acceptance before a production-readiness claim.
